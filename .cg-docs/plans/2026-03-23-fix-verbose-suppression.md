# Plan: Fix verbose suppression in st_init, st_save, st_load

## Objective

Ensure that `st_init()`, `st_save()`, and `st_load()` emit zero informational
messages or warnings when `verbose = FALSE`. Currently `st_init()` lacks a
`verbose` parameter entirely, and all three functions may leak messages through
internal helpers.

## Context

- `st_save()` and `st_load()` already have `verbose` parameters and gate most
  messages behind `isTRUE(verbose)`. However, some paths (e.g. alias-conflict
  warnings inside `st_init`, the `st_register_format` inform) may still produce
  output.
- `st_init()` has no `verbose` argument — it always emits informational
  messages ("stamp initialized", alias rebasing, duplicate-alias warnings).
- The existing test `test-save-load.R` ("st_save and st_load respect verbose
  flag") already uses `expect_silent()` for `verbose = FALSE` calls.
- `.st_normalize_user_path()` already accepts and respects `verbose`.
- Format handlers are wrapped by `.st_wrap_reader`/`.st_wrap_writer` that
  suppress warnings when `verbose = FALSE`.

## Implementation Steps

### 1. Add `verbose` parameter to `st_init()`

- **Files**: `R/IO_core.R`
- **Details**:
  - Add `verbose = TRUE` to `st_init()` formals.
  - Add `@param verbose` roxygen2 documentation.
  - Add input validation: `stopifnot(is.logical(verbose), length(verbose) == 1L, !is.na(verbose))`
  - Gate the four informational `cli::cli_warn`/`cli::cli_inform` calls at
    lines 22, 41, 67, 92 behind `if (isTRUE(verbose))`.
  - Leave `cli::cli_abort()` calls (lines 18, 28, 47) unconditional — these
    are genuine errors.
- **Tests**: See step 3.
- **Acceptance criteria**: `st_init(td, verbose = FALSE)` emits no messages,
  warnings, or output. `st_init(td, verbose = TRUE)` behaves as today.

### 2. Verify `st_save` and `st_load` are fully silent

- **Files**: `R/IO_core.R`
- **Details**:
  - Review every code path in `st_save()` and `st_load()` end-to-end for
    ungated messaging. Based on the audit above, all messages are already
    gated. No code changes expected, but verify by running the existing
    `expect_silent()` tests.
- **Tests**: Run existing test suite; if any `expect_silent` assertions
  fail, gate the offending message.
- **Acceptance criteria**: `expect_silent(st_save(..., verbose = FALSE))`
  and `expect_silent(st_load(..., verbose = FALSE))` pass.

### 3. Add/expand tests for `st_init(verbose = FALSE)`

- **Files**: `tests/testthat/test-save-load.R`
- **Details**:
  - Add a new test block `"st_init respects verbose flag"` that:
    1. `expect_message(st_init(td), "stamp initialized")` for default
       verbose = TRUE.
    2. `expect_silent(st_init(td2, verbose = FALSE))` for verbose = FALSE.
    3. Optionally test the alias-rebase and duplicate-alias scenarios
       with `verbose = FALSE` to confirm warnings are suppressed.
- **Acceptance criteria**: All new tests pass; `R CMD check` has no
  regressions.

### 4. Update `man/` documentation

- **Files**: `man/st_init.Rd` (auto-generated by roxygen2)
- **Details**: Run `devtools::document()` to regenerate Rd files after
  the roxygen2 changes.
- **Acceptance criteria**: `man/st_init.Rd` includes the `verbose` parameter.

## Testing Strategy

- **Unit tests**: `expect_silent()` for all three functions with
  `verbose = FALSE`; `expect_message()` for `verbose = TRUE`.
- **Edge cases**: alias-conflict paths in `st_init`, skip-save path in
  `st_save`, hash-mismatch path in `st_load`.
- **Integration**: `R CMD check --as-cran` should pass cleanly.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Breaking existing callers of `st_init()` | Default is `verbose = TRUE` — fully backward compatible. |

## Out of Scope

- Adding verbose to other functions (e.g. `st_info`, `st_restore`,
  `st_register_format`). Those can be addressed in a follow-up.
- Changing the behavior of `cli::cli_abort()` — errors are never suppressed.
